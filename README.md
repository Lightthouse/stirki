# Стирки On

![stirki](./stirki_bot_logo.jpg)

# Проект по организации стирок в жилых районах.

# Основная концепция сервиса
Клиенту нужно постирать одежду и он решает, что проще будет отдать эту работу другим людям.
Клиент заходит в телеграм/pwa приложение и создает заявку, указывает количество одежды для стирки и выбирает
дополнительные услуги (отбеливатель, кондиционер и т.д.)
К клиенту приходит курьер и забирает  одежду. Он относит одежду в нашу прачечную. Мы стираем и сушим одежду.
Когда всё готово, курьер берет постиранные вещи и относит обратно клиенту.

# Технические моменты
Так как проект запускается в тестовом режиме и всего для 12 домов, где примерно 6000 квартир - использование
громоздкой инфраструктуры избыточно. Но, желательно иметь возможность к масштабированию проекта.
Проект необходимо развернуть на vps сервере. Необходимо добавить логирование для отслеживания проблем.
Возможно, стоит разнести проект на backend и frontend репозитории.

## backend
Используется python 3.12 - 3.14. Пока что без фреймворка, но, возможно стоит всё же его использовать.
Через docker compose устанавливаются база данных postgresql и baserow для просмотра таблиц.
В качестве orm используется tortoise.
Стоит задуматься о переносе проекта на fastapi с использованием sql alchemic.
Стоит задуматься о добавлении pg bounce для отказоустойчивости базы данных.
Стоит задуматься о добавлении брокера очередей для отказоустойчивости.

## frontend
Изначально планировалось реализовать взаимодействие с клиентом по средствам телеграм бота.
И уже подготовлен скелет диалога в папке bot. Но из-за технических особенной решено было перейти на использование
pwa приложения.

## kaiten
Для удобства отслеживания заказов используется канбан доска на сайте kaiten.ru.
При создании нового заказа создается карточка задачи с информацией о заказе.
Каждый статус заказа выделен в отдельный столбец. При изменении статуса - карточка перемещается менеджером.
При переходе карточки на статус "доставка" - клиенту так же приходит уведомление.

## оплата
Пока что оплата не настроена. В telegram боте использовалась тестовая интеграция с юкассой.
Интеграция хорошо работала, но не имела оплату по СБП или qr коду. Хотелось бы иметь эти функции у себя.


## мониторинг клиентов
Заказы клиентов трекаются в kaiten. Но, так же хотелось бы иметь возможность видеть клиентов, которые зашли в
приложение, но не сделали заказ. Это можно смотреть напроямую в базе данных, но менеджерам это будет неудобно.
В данный момент предполагается использовать baserow, который устанавливается в docker.



# Использование
Добавить .env файл   

Создать тестовые заказы:
```bash
uv run -m test_db seed
```

Поднять телеграм бота:
```bash
uv run -m src.bot.main
```
