"amount": "1.00",

## 🟠 Высокий

### 2. `src/api/routers/auth.py:30` — Нет rate-limiting на `/api/auth/request-code`

Бесконечный цикл запросов — SMS-бомбардировка любого номера телефона за счёт сервиса. Нет throttle ни по IP, ни по номеру.

### 3. `src/repositories/client.py:53` — 4-значный SMS-код можно перебрать без блокировки

10 000 комбинаций, нет счётчика неудачных попыток и нет локаута. За несколько секунд в цикле можно войти в любой аккаунт.

### 4. `src/api/routers/orders.py:44` — Обход бесплатного тарифа: платные допуслуги сохраняются с ценой 0 ₽

При `is_free=True` сервер не валидирует список `services`. Можно отправить `{is_free: true, services: ["conditioner", "ironing", "vacuum_pack"]}` — все услуги будут добавлены к заказу бесплатно.

Фикс: при `is_free=True` отклонять запросы с любыми `services`, кроме разрешённых на бесплатном тарифе (или просто игнорировать их и передавать пустой список).

### 5. `src/api/routers/orders.py:35` — Гонка при создании заказа: два одновременных запроса создадут два активных заказа

Проверка `has_active_order` и создание заказа — не атомарная операция. Два параллельных запроса оба пройдут проверку до коммита первого.

Фикс: `SELECT FOR UPDATE` / advisory lock, или уникальный частичный индекс в БД по `(client_id)` WHERE статус не завершён.

## 🟡 Средний

### 6. `frontend/src/pages/OrderPage.tsx:117` — `verifyPayment` fire-and-forget: отклонённый платёж молча показывает «Заказ принят»

```tsx
verifyPayment(result.order_id).catch(() => {})  // результат никуда не идёт
```

Если Точка Банк отклонила оплату, бэкенд отменяет заказ, но фронтенд уже показывает StatusScreen со статусом «Заказ принят». Первый polling — через 60 секунд.

### 7. `frontend/src/components/StatusScreen.tsx:33` — Первый polling через 60 секунд, «слепое» окно статуса

`setInterval` стартует с задержкой 60 000 мс без немедленного первого запроса. Для пользователей, вернувшихся после оплаты, статус устаревший целую минуту.

Фикс: вызвать `getOrder` один раз сразу внутри `useEffect`, затем запустить интервал.

### 8. `frontend/src/components/CartMini.tsx:11` — Зачёркнутая цена в мини-корзине не включает цены допов

```tsx
// CartMini (неверно):
const fullTotal = cart.reduce((sum, item) => sum + item.basePrice, 0)

// CartExpanded (верно):
const fullTotal = cart.reduce((sum, item) => sum + item.basePrice + item.addons.reduce((s, a) => s + a.price, 0), 0)
```

Если в корзине есть допуслуги, зачёркнутая цена в плавающем бейдже будет меньше, чем в раскрытой корзине.

## 🟢 Низкий

### 9. `frontend/src/components/swipe/AddressCard.tsx:75` — Гонка загрузки адресов и профиля может перезаписать сохранённый дом

Если `getAddresses()` резолвится раньше `getMe()`, а потом смена `data.street` (из профиля) снова тригерит `useEffect`, дом сбрасывается на первый в списке вместо сохранённого.

### 10. `src/repositories/client.py:31` — `commit()` в `get_by_token()` пишет в БД на каждый запрос, включая упавшие

Продление токена коммитится в auth-зависимости до выполнения роутера. Если роутер потом откатит транзакцию — продление уже записано. Плюс лишний round-trip к БД на каждый запрос, включая частые polling-запросы статуса заказа.
