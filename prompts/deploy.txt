 Деплой на VPS

 Контекст

 Приложение готово к деплою — есть compose.yml с prod-профилем, Dockerfile.backend, Caddyfile, run.sh prod. Нужно подготовить инфраструктуру и скрипт деплоя для запуска на VPS
 без домена (по IP-адресу).

 Проблема: HTTPS без домена

 Caddy автоматически выдаёт SSL-сертификат через Let's Encrypt, но только для доменов. По IP-адресу HTTPS не работает «из коробки». Варианты:

 Рекомендация: HTTP-only по IP — пока нет домена, Caddy будет работать на порту 80 без SSL. Это нормально для тестирования командой. Когда появится домен — достаточно прописать
 DOMAIN=... в .env и перезапустить.

 Что нужно сделать

 1. Изменения в коде для поддержки работы по IP (без домена)

 Caddyfile — добавить поддержку HTTP-only режима:
 {$DOMAIN:localhost} {
     ...
 }
 Когда DOMAIN=:80, Caddy слушает на порту 80 без SSL. Нужно задокументировать это в .env.example.

 compose.yml — изменить FRONTEND_URL и YOOKASSA_RETURN_URL в backend environment:
 - Сейчас: FRONTEND_URL: https://${DOMAIN} (хардкод https)
 - Нужно: вынести полный URL в переменную, чтобы можно было указать http://IP_АДРЕС

 src/api/app.py — CORS origins уже берётся из FRONTEND_URL, ничего менять не нужно.

 Frontend — использует относительные пути /api, работает с любым хостом. Изменений не нужно.

 2. Добавить скрипт/инструкцию для первоначальной настройки сервера

 Создать deploy/README.md с пошаговой инструкцией:

 1. Выбор VPS — рекомендация: Timeweb Cloud / Selectel / reg.ru VDS, минимум 1 vCPU, 1 GB RAM, Ubuntu 24.04
 2. Первичная настройка — обновление системы, установка Docker
 3. Клонирование репозитория и настройка .env
 4. Запуск ./run.sh prod
 5. Проверка работы по http://IP_АДРЕС

 3. Конкретные изменения в файлах

 compose.yml (строки 33-34)

 # Было:
 FRONTEND_URL: https://${DOMAIN}
 YOOKASSA_RETURN_URL: https://${DOMAIN}

 # Стало:
 FRONTEND_URL: ${FRONTEND_URL:-http://localhost}
 YOOKASSA_RETURN_URL: ${YOOKASSA_RETURN_URL:-http://localhost}

 .env.example — добавить переменные

 # URL фронтенда (для CORS и редиректов)
 # Без домена: http://IP_АДРЕС
 # С доменом: https://stirki-on.ru
 FRONTEND_URL=http://localhost
 YOOKASSA_RETURN_URL=http://localhost

 Caddyfile — без изменений

 Текущий {$DOMAIN:localhost} уже поддерживает IP-доступ. Для работы по IP нужно установить DOMAIN=:80 в .env.

 deploy/README.md — новый файл с инструкцией деплоя

 Файлы для изменения

 - compose.yml — убрать хардкод https:// из environment
 - .env.example — добавить FRONTEND_URL, YOOKASSA_RETURN_URL, пояснения для DOMAIN
 - deploy/README.md — новый, инструкция деплоя на VPS

 Проверка

 1. Локально: ./run.sh prod с DOMAIN=:80 и FRONTEND_URL=http://localhost — приложение должно открыться на http://localhost
 2. На сервере: приложение доступно по http://IP_АДРЕС, API отвечает на /api/health
